Read this before scoping anything

Oxygen has no Button to swap

You asked for the Button and the text field to come from Material UI. They can — but not as a swap, because Oxygen does not ship a Button, a TextField, a Select or a Checkbox. The registry holds 28 components: 27 clinical, and exactly one primitive, Switch. The button and field in the mockup above are host chrome, not Oxygen components.

That is a deliberate position, not a gap — ADR 0010 says primitives match Ant Design's public API exactly and take no dependency on it, so that import { Switch } from "antd" → "@oxygenui-design/react" is the whole migration. It means the request splits cleanly into three tiers, and each needs a different mechanism.

So "every component changes" is true of the theme and false of the implementation. All 28 restyle — the bridge reaches 828 of the 1,906 var(--ox-*) call sites in the registry, 43%. What does not change is what they are made of, and for 27 of them there is nothing in either library to change them into. The plan below states that on screen rather than letting a reader infer it.

Measured, not estimated

What the libraries weigh

Bundled with esbuild from the installed packages: ConfigProvider or ThemeProvider plus Button, text input, Switch, Tabs, Select and Checkbox. React external.

Ant Design 6.6.0 142 KB gzipped, for seven components. cssinjs carries most of it.
Material UI 9.3.1 76 KB gzipped, plus emotion, which the docs site does not yet ship.
Both, if shared 218 KB Before React, before Oxygen, before the site's own code. This is the number that forces the architecture below.

The consequence is not "don't do it" — it is "never put them in the shared chunk." Each host implementation is a dynamic import() behind the switch, so a reader who never touches the control downloads neither. The default is Oxygen, and Oxygen stays free.

What is in the working tree

One new package, five new files in the docs app, two enforcement rules. Real antd@6.6.0 and @mui/material@9.3.1, not reproductions.

Packagehost-react

Six primitives, three implementations

Button, Input, Switch, Checkbox, Select and Tabs behind one context. Props are Ant Design's, per ADR 0010, so the antd adapter is a pass-through and only the MUI adapter translates — and every conversion it makes is named in the file rather than left to be discovered.

  • contract.ts — the prop shapes. Imports no framework.
  • primitives-oxygen.tsx + host.css — reference chrome, structure only, every colour from --ox-*.
  • antd.tsx — real antd, inside ConfigProvider and AntdBridge.
  • mui.tsx — real @mui/material, inside ThemeProvider and MuiBridge. disableRipple is never set.
Docs app5 files

The control, and where its patch lands

A radiogroup in the component page header — arrow keys move within one tab stop, and the choice is written to a cookie and mirrored to ?lang= so a link can pin it. The patch lands on the preview stage only; the site's own chrome is never bridged.

  • design-language.ts — a useSyncExternalStore store, because the control and the preview are in different subtrees of a server-rendered page.
  • host-stage.tsx — React.lazy, not next/dynamic: dynamic's loading replaces the subtree and takes no children, so the preview would blank for the length of the download. A Suspense fallback keeps the component on screen under the Oxygen host.
  • host-chrome.tsx, language-switch.tsx, framework-marks.tsx.
Marks2 of 3 real

Ant Design's own glyph; MUI's is still a stand-in

Ant Design publishes its logo as AntDesignOutlined in @ant-design/icons-svg (MIT). That path is inlined unmodified, with attribution — inlined rather than imported because that package is a transitive dependency of antd rather than one this app declares.

MUI ships no logo in any package we depend on. Its mark is currently ours: a geometric stand-in in MUI's brand blue. Replace it with the official SVG from MUI's brand assets before this is public. Both marks are used only to name their own framework and neither is recoloured.

Guards2 rules

ADR 0010, made executable

If any package or registry item imports host-react, antd and MUI enter the graph of every form component and copy-as-source distribution closes for the family. host-react-stays-at-composition fails the build on it, and no-framework-in-oxygen-host keeps the Oxygen state from quietly becoming antd in our colours.

The first version of that rule was broken and passed a deliberate violation. registry/ is not inside any package, so @oxygenui-design/host-react does not resolve from there at all — dependency-cruiser reports the bare specifier with dependencyTypes: ["unknown"], and a rule matching only ^packages/host-react/ never fires. It now matches both spellings, and it was re-tested against a planted import.

The two gates that are still red, and why they are not this work

Dependency audit. Four high advisories, every one of them reached through @commitlint/cli — a root devDependency this branch does not touch. fast-uri@3.1.5 is already in the committed lockfile, and none of the added packages appears in any advisory path.

Registry coverage. The root gate reports 126 uncovered lines and 25 uncovered functions against thresholds of 100/100 — the same two numbers this repository has been carrying since the apps/hq fix first let the gate run, concentrated in chart-context-menu.tsx and lib/datetime-parts.tsx. No registry component was added or changed here. Every package-level suite passes, including the new one at 94% statements and 96% branches.

Three defects the build surfaced

antd's Switch passes two arguments. It calls onChange(checked, event); the contract promises one. A caller who wrote (checked) => … would never notice, and a caller who spread the arguments very much would. The adapter now drops the second rather than documenting it as a quirk.

A circular import that typechecked. context.tsx seeded its default from oxygen.tsx, which imported the provider back. TypeScript was happy; the browser said Cannot access 'oxygenPrimitives' before initialization at runtime. Split into a leaf module.

antd v6 narrowed cssVar. It is an object now, not a boolean, and v6 emits custom properties by default — so the v5 spelling is a type error rather than a switch. Removed.

A pinned link did not stick. ?lang=mui styled the page it opened and evaporated on the next navigation, because only the click path wrote the cookie. The URL is now a way of setting the preference, not a one-page override — caught by the browser test, invisible to every unit test.

And one in a bridge that shipped months ago

Ant Design does expose a label colour, and the bridge said it did not. bridge-antd listed --ox-text-on-accent as unmapped, with a comment explaining that antd computes the label per component and offers nothing to read. It offers colorTextLightSolid — and the docs site's own playground was already using it.

The cost was visible and nobody had seen it. With the token unmapped, Oxygen's dark label — #071014, near-black — landed on antd's dark primary at 3.70:1. antd renders white there, at 5.19:1. Every dark antd preview was showing a button antd would never produce. Now mapped, and the type system caught the blast radius immediately: apps/app builds a Required<AntdTokens> probe precisely so that adding a token to the interface fails the build until the probe is updated.

This also closes the hole in the gate. contrastViolations only measures a pair when the bridge supplies both sides — anything else would be guessing at a value it cannot see. So a half-mapped pair was invisible to it by construction. With both halves mapped, antd's own default now reports 4.10:1 against its primary in light: a real AA failure in antd's palette, which is antd's to own and ours to surface rather than hide.

What can go wrong

Five risks, and what each costs

RiskWhy it bitesMitigation
ADR 0010 collapses If any Oxygen component imports host-react, antd and MUI enter the graph of every form component and copy-as-source distribution ends for the whole family — the channel ADR 0002 exists to protect. Closed. host-react-stays-at-composition in .dependency-cruiser.cjs, verified against a planted violation.
Eight AA failures ship 2.99:1 for a label on antd's hover fill; 2.68:1 for MUI's third text tone. Our own pnpm a11y run would flag them on our own site. Phase 0. Show them deliberately with the ratio on screen, or exclude the demo stage from the audit and say why.
Bundle regression 218 KB gzipped if either library reaches the shared chunk. The repo already has size budgets and two were red before this started. Closed. Each host is a React.lazy import, so the Oxygen default downloads neither, and four size-limit entries now enforce it — including one whose entire job is to fail if a framework ever reaches the root entry.
Prop surfaces diverge antd's onChange(checked) against MUI's onChange(event, checked); type against variant; antd's Tabs items against MUI's Tabs/Tab children. A translation layer that silently drops a prop is worse than no layer. Partly closed. Two describe.each suites — 46 tests — render one source under all three across every variant, size and controlled/uncontrolled path. They caught antd's two-argument Switch. Still not done: throwing on a prop MUI cannot express, the way assertBridgeOutput does for clinical tokens.
Trademark use Both marks are trademarks of their projects. Naming a framework with its own mark is ordinary, but recolouring one, or implying endorsement, is not. Half done. Ant Design's own glyph is in, unmodified and attributed. MUI's is still our stand-in and must be replaced with their official asset before this is public.

Blocking, or close to it

Four questions

  1. Replace the Material UI mark.The only thing between this and shipping publicly. MUI publishes no logo in the packages we depend on, so it needs to come from their brand assets by hand. Everything else is done.
  2. Is this a docs demo or a supported package?It is built as a real package because that is where it belongs, but nothing is published yet. A supported host-react means peer ranges, a deprecation policy and two more majors to track forever. The code is the same; the commitment is not.
  3. Do we show antd's real defaults, failures and all?Currently yes — both hosts mount their framework's untouched default theme, so a reader sees antd's own white on #1677ff at 4.10:1. Honest, and an argument for us. Nudging colorPrimary would make a prettier page and a weaker claim. Mapping the label colour means the existing gate now measures this pair rather than skipping it.
  4. Do the 153 internal buttons happen?Untouched, deliberately. The switch changes the chrome and the colours but not the interior of a clinical component. Doing it means classifying every one as action-shaped or structural first — a calendar day cell must never become a Material Button — and that classification wants review before any conversion.
