01 · The short version

Recreate it natively, package it once, ship it everywhere.

Recommendation

Build the loader as native SVG + CSS keyframes — not as a Lottie playback. The reference is one teal stroke: an open heart that beats and an ECG line that redraws itself through the gap. That is ~2 KB of SVG and CSS, needs no runtime, themes through Oxygen tokens, respects reduced motion for free, and — decisively for a page loader — works before any JavaScript bundle has loaded.

Package one art source three ways: the shadcn registry item for React (Oxygen’s channel), a dependency-free Custom Element <ox-loader> for Vue, Angular, Svelte and any other stack, and a copy-paste HTML/CSS snippet for the no-JS boot screen. One parity test keeps the three identical.

What this brief contains

  • A frame-by-frame teardown of the reference Lottie — its structure, timing, and the two flaws worth fixing.
  • Pulse (the recreation) plus five alternatives — Trace (heartbeat only), Breath, Cross, Helix, Fill — all running live below, on light and dark stages.
  • An interactive configurator driven by a working <ox-loader> prototype, with generated React / Vue / Angular / HTML usage.
  • The full prop / attribute / token / part / event contract, the repo file layout and meta.ts, install commands per framework, and the SSR and boot-screen recipes.
  • Accessibility and standards checklist, performance budget, a story-derived test plan, delivery phases, and the decisions only you can make.

Default cadence

60 bpm

Sinus rhythm at rest. Configurable 40–100; the reference beats at exactly this rate.

Payload

≈ 2 KB CSS · ≈ 3 KB JS

Gzipped. The Lottie route is 8 KB of JSON plus a 40–70 KB player.

Frameworks

React · Vue · Angular · any

Custom Elements v1 + one native React item. Svelte, Solid, Rails, Django, static HTML all covered by the element or the snippet.

02 · Purpose and fit

What a page loader has to do in a healthcare app

It is the first thing a clinician or a patient sees, it plays while the system is at its most fragile, and it is judged in the first 300 ms. The bar is “alive and calm”, not “busy”.

Where it appears

App boot
Inline in index.html, before the framework bundle arrives. This is the case that rules out a JS-driven player.
Route change
Full-page or region overlay while a chart, worklist, or results page resolves.
Panel
Overlay on one card while it re-fetches — the rest of the record stays usable (per CONTENT.md §5, failure and waiting stay contained).
Inline
Small (20–32 px) beside a button label or a table row. Two of the six variants read at that size.

Where it sits in Oxygen

Layer
primitive — no FHIR input, no clinical logic. Registry name loader; React exports Loader and a PageLoader preset.
Depends on
tokens (colour, density) and utils. Nothing else — zero npm dependencies, per README’s “Runtime: 0”.
Precedent it sets
First component with a framework-agnostic core. ARCHITECTURE §2 already reserves L0/L1 for exactly this (“L0 holds no React… keeps a future non-React target from being a rewrite”).
Replaces
Nothing yet. ClinicalSkeleton (content-shaped placeholders) will return later and complements this: skeleton for known layouts, loader for unknown waits.

03 · Reference teardown

What the Lottie actually is, frame by frame

Pulled from the animation JSON (q3QbAe1Rrl.json, 8.2 KB) rather than eyeballed. Everything below is measured.

Structure

Format
Lottie 5.5.7 · 173 frames @ 24 fps = 7.21 s loop · 3840 × 2160 comp · 1 shape layer, 0 assets.
Ink
One stroke, #43BEB7, width 30 comp units (2.4 % of the heart’s width), round caps, miter joins, no fill.
Heart
Two open paths: the two lobes (one cubic path, 10 vertices) and the bottom “V”. The sides are deliberately left open at mid-height so the ECG line can pass through.
ECG line
One 18-vertex path, wider than the heart, running horizontally through the gap: bump ▲ spike ▼ deep dip ▲ spike, then flat.
Colour source
Same teal family as Oxygen’s accent (--ox-accent = #059478 light / #67e8f9 dark), so tokenising it costs nothing.

Motion

Heart draws in
Trim path 100 → 0 over 17 frames (0.7 s), ease-out — then stays.
Heart beats
Scale 100 → 110 → 100 every 24 frames = 1.0 s (60 bpm), ease-in-out (bezier ≈ 0.33/0 → 0.67/1). Symmetric, no “lub-dub”.
Line sweeps
Trim path draws the line left→right in 20–21 frames (0.85 s), then either erases from the left over 6 frames or resets in 2. Seven sweeps per loop, one per beat.
Sync
Sweep and beat share the 1.0 s period — the line’s spike lands as the heart expands.

Keep

  • The concept: open heart + ECG through the gap. Reads at a glance as “care” without a red cross or a stethoscope.
  • The line-weight discipline: one thin stroke, one colour, no fill. That is what makes it calm.
  • 60 bpm with symmetric ease-in-out. It is measurably a resting rhythm.
  • The draw-in entrance. It turns “appear” into “arrive”.

Fix

  • Loop seam. The heart re-draws itself at frame 0 of every loop, so every 7.2 s the heart vanishes and redraws. Ours draws once on mount; only the beat and sweep loop, seamlessly.
  • Inconsistent sweep. Some passes erase, some snap. Ours uses one monitor-style sweep — a bright head with a fading tail — over a faint static track, so the shape never disappears between beats.
  • Baked colour and size. Ours is currentColor, sized by a CSS variable, stroke width constant in pixels at any size (vector-effect: non-scaling-stroke).
  • No accessibility, no reduced motion, no SSR. All three are first-class below.

04 · Design principles

“Soothing” is a set of numbers, not an adjective

Every variant below is held to the same six rules. They are also the review checklist for any future loader.

Cadence at rest

Cardiac variants beat at 60 bpm by default (range 40–100). Breath cycles at 15/min (4 s). Nothing cycles faster than 1.7 Hz; nothing flashes above WCAG’s 3 Hz threshold.

Small amplitude

Beat scale ≤ 7 %. Rings fade before they reach full size. Dots travel ≤ 12 units. Motion should be noticed peripherally, never tracked.

Sine-like easing

cubic-bezier(.45,0,.55,1) for cycles, ease-out for entrances. No linear spins, no springs, no overshoot.

One ink, faint track

Accent stroke on a 22 % track. The track keeps the shape legible between beats and passes 3:1 non-text contrast on both grounds.

Alive, not busy

Loops must be seamless (first frame ≡ last frame). No spinners: rotation implies “working hard”; a pulse implies “still here”.

Honest about time

Delay before showing (avoid flashes), minimum visible time (avoid flicker), a slow-wait message after 8 s. A loader that hides that the system hung is a clinical risk.

Two healthcare-specific cautions

  • Never a red cross. The red cross on white is a protected emblem (Geneva Conventions; national law in most markets). The Cross variant is always in the accent hue, and the docs say so.
  • A beating heart is not neutral everywhere. In a resuscitation or oncology workflow it can read as glib. Trace and Breath exist so a product can pick a variant that fits its clinical context; the DESIGN.md contract gets a “Loading” line to record that choice.

07 · Configuration API

        
One contract, three surfaces

        
Attributes on the element, props on the React component, and CSS custom properties for anything visual. Names are identical across surfaces (kebab-case on the element, camelCase in React). Defaults are chosen so <ox-loader> with no attributes is already correct.

08 · Architecture & install

        
One art source, two thin shells, one parity test

        
The motion lives in CSS and the shapes in SVG. Neither knows about React or the DOM API. Everything framework-specific is a shell around that core, and the shells are tested to render identical markup.

Server rendering

        
React: the registry item is a client component with no effects on first paint — it renders the SVG on the server and hydrates cleanly. Element: ships a declarative-shadow-DOM template so Nuxt, Angular Universal, and Astro emit the loader in HTML; on hydrate the element adopts the existing shadow root instead of re-rendering. React 19 passes attributes and events to custom elements natively; for React 18 hosts the docs recommend the registry item over the element.

      

    


    
    

      

        
09 · Accessibility & standards

        
The rules it is built against

      

      

        

          
WAI-ARIA & WCAG 2.2

          
    
            
  • Indeterminate: role="status" (implicit aria-live="polite") with the label as accessible name; announced once on show, once on hide (“Loaded” is the app’s job).
    • 
            
  • Determinate: role="progressbar", aria-valuemin/max/now, aria-valuetext (“42 percent”); throttled to announce every 10 %.
    • 
            
  • The region being loaded gets aria-busy="true" (React item exposes busyRef; element exposes for="id").
    • 
            
  • 2.2.2 Pause, Stop, Hide: a preload indicator is the documented exception (“part of a preload phase… not indicating progress could confuse users”); we still expose motion="reduced".
    • 
            
  • 2.3.1 Three flashes: max cadence 100 bpm = 1.67 Hz, amplitude ≤ 7 %, no full-field luminance change.
    • 
            
  • 2.3.3 Animation from interactions (AAA): honoured via prefers-reduced-motion; the still state is designed, not just paused.
    • 
            
  • 1.4.11 Non-text contrast: stroke ≥ 3:1 on both grounds; track is decorative and exempt, but the still state raises it to 100 %.
    • 
            
  • 1.4.3 / 1.4.6: label and hint use --ox-text / --ox-text-muted, already contrast-checked in the token build.
    • 
            
  • No focus trap; page mode does not steal focus; scroll lock is released on hide and on unmount.
    • 
          

        

        

          
Platform & ecosystem standards

          
    
            
  • Custom Elements v1 + Shadow DOM, ElementInternals for role/aria, ::part() hooks, CSS custom properties across the boundary — scores 100 % on custom-elements-everywhere for Vue, Angular, Svelte; React 19 native.
    • 
            
  • Declarative shadow DOM for SSR; customElements.whenDefined guard for late upgrades.
    • 
            
  • Design tokens: only --ox-*; the loader adds a component.loader group to the DTCG source, so brand overrides go through the token build (ADR 0005), never CSS overrides.
    • 
            
  • Forced colours: @media (forced-colors: active) → stroke CanvasText, scrim Canvas, no opacity-only cues.
    • 
            
  • RTL: the ECG sweep runs start→end (logical); everything else is symmetric. Logical properties only (lint enforces).
    • 
            
  • Content: label/hint/slow-hint follow CONTENT.md — name the wait, say what remains usable, no “Something went wrong”.
    • 
            
  • Security constraints (ADR 0009): no fetch, no env, no console, no innerHTML from input — lint-enforced on the registry file; the element package is held to the same rules.
    • 
            
  • Reduced-data / battery: page mode pauses animations when the tab is hidden (visibilitychange) — the one JS behaviour worth having.
    •

13 · Decisions & risks

        
What only you can decide, and what could bite

      

      

        

          
Decisions

          
    
            
  1. Name. loader (Loader + PageLoader) vs page-loader. Recommend loader — one component, three modes; the page case is a preset.
    2. 
            
  2. v1 variant set. Pulse, Trace, Breath, Fill now; Cross and Helix in v1.1. Recommend that split — it covers brand, clinical, patient, and progress.
    3. 
            
  3. Default rhythm. 60 bpm and 7 % beat (reference is 60 / 10 %). Recommend 60 / 7 %; 10 % feels eager at 88 px.
    4. 
            
  4. Element now or later. Ship @oxygenui/loader alongside the registry item, or React first. Recommend alongside — the prototype already exists and it is the multi-framework promise.
    5. 
            
  5. Where the CSS lives. Own loader.css registry file vs folding keyframes into the tokens stylesheet. Recommend own file; tokens stay declarative.
    6. 
            
  6. Slow-wait copy. Approve “Still loading. You can keep waiting or go back.” for both registers, or write two.
    7. 
            
  7. Reduced-motion still state. Opacity breath (proposed) vs fully static. Recommend opacity breath — motion-safe and still signals “working”.
    8. 
          

        

        

          
Risks and mitigations

          
    
            
  • Two renderers drift. Mitigated by the parity test and by generating the JSX art from art.ts if drift ever occurs.
    • 
            
  • React 18 hosts and custom elements. Attribute/event quirks pre-19; docs steer React users to the registry item.
    • 
            
  • Emblem law. Cross never red; docs and lint (no-primitive-token) prevent a raw red on it.
    • 
            
  • Symbol fit. Heart may be wrong for some workflows; variants exist and DESIGN.md records the choice.
    • 
            
  • Vestibular safety. Amplitudes are small and reduced motion is honoured; the motion QA checklist is a release gate.
    • 
            
  • Boot-screen removal. If the app forgets to hide the inline loader, users wait forever; the recipe includes the hide call and a 20 s watchdog that reveals a “Reload” action.
    • 
            
  • Perf on old tablets. Helix is the heaviest (18 nodes); it is v1.1 and gated by the 4× throttle test.
    •
