# Bundle budgets

`.size-limit.json` is the enforced version of ENGINEERING.md §11.

The budget is on **installed bytes**, not repository size: a component library's
value proposition is what a customer ships to their users, and everything else
is our problem rather than theirs.

Limits sit just above today's measured size so they **ratchet rather than
aspire**. When a number here goes up, that is a decision someone made in a pull
request — which is the point. Lower them when you can; never raise one to make
a build pass.

React and react-dom are excluded from the React measurements because they are
peer dependencies the host already has.

## The barrel moved from 9 KB to 24 KB in the Consult release

Recorded here because the rule above says a raised number should be a decision
somebody made in a pull request, not a build turning green.

Every earlier entry measured a **loader** — a few hundred lines of SVG and
timing. Consult is the first `pattern`-layer component, and it carries an engine:
a session state machine, a safety pipeline, mode scope contracts, and FHIR audit
mapping. Measured alone it is 21.5 KB, and the barrel is 23.81 KB, so essentially
all of the growth is Consult and essentially none of it is drift in the loaders.

Two things keep this honest rather than a blank cheque:

- **`react — consult alone` is the number that matters.** The barrel is an
  install-everything convenience; almost no consumer imports it. What a customer
  actually ships is one component, and that entry is budgeted at 22 KB against a
  measured 21.5 KB, ratcheting like every other line here.
- **The engine is where any future growth should be caught.** `consult-core` is
  dependency-free and framework-free by design. If it starts pulling weight,
  that is the entry to add next — not a further barrel raise.

If the barrel budget is meant to model "what a small consumer ships", it has
stopped doing that now that one component dominates it, and splitting it per
layer would say more than one number can.
